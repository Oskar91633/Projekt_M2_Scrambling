01 / Naiwny scrambling Etap porażki
Deterministyczne przesunięcie wierszy i kolumn (cykliczne, sterowane kluczem). Brak chaotyczności — lokalne struktury obrazu przetrwają. Funkcja scramblingу: dst[(y+k₁)%H][(x+k₂)%W] = src[y][x]. Unscrambling: operacja odwrotna tymi samymi kluczami.
// ALGORYTM SCRAMBLING — Etap 1
for y in [0..H): for x in [0..W):
  dst[(y + key1) % H][(x + key2) % W] = src[y][x]

// ALGORYTM UNSCRAMBLING — Etap 1 (funkcja odwrotna)
for y in [0..H): for x in [0..W):
  dst[(y - key1 + H) % H][(x - key2 + W) % W] = scrambled[y][x]
Parametry
Błędny klucz (+1 do k₁ i k₂) — symulacja ataku
Akcje
Słabości metody: Szachownica i gradienty pozostają w pełni rozpoznawalne — lokalna korelacja pikseli nie ulega zniszczeniu. Periodyczność przesunięcia umożliwia atak brute-force.

02 / Czysta permutacja sterowana kluczem P⁻¹(P(i))=i
Permutacja Fisher-Yates sterowana seedem. Brak zmiany wartości pikseli — tylko zmiana kolejności. P : {0…N-1} → {0…N-1} — funkcja bijekcyjna. Unscrambling przez jawną funkcję odwrotną P⁻¹.
// ALGORYTM SCRAMBLING — Fisher-Yates (seed-controlled)
perm = fisherYates(N, seededRNG(seed))  // permutacja P
for i in [0..N): dst[perm[i]] = src[i]

// ALGORYTM UNSCRAMBLING — funkcja odwrotna P⁻¹
inv = inversePerm(perm)  // inv[perm[i]] = i
for i in [0..N): dst[inv[i]] = scrambled[i]
Parametry permutacji
Błędny klucz (seed+1) — test efektu lawinowego
Akcje
Odpowiedź na pytania: Brak efektu lawinowego — histogram pikseli identyczny z oryginałem. Known-plaintext attack rekonstruuje P w czasie O(N).

03 / Mechanizm wzmacniający — Hybryda C Perm + Substytucja
Klasa C: Permutacja Fisher-Yates + Substytucja XOR sekwencją z mapy logistycznej xn+1 = r·xₙ·(1−xₙ). Kolejność: substytucja f(p,k) → permutacja P. Unscrambling: P⁻¹ → f⁻¹ = f (XOR jest własną odwrotnością).
// ALGORYTM SCRAMBLING — Hybryda (substytucja → permutacja)
logSeq = logisticMap(r, x0, N)  // 500 iteracji burn-in
for i in [0..N): key = floor(logSeq[i] * 256)
  tmp[i].R = src[i].R ⊕ key  G = src[i].G ⊕ ((key*131+17) & 0xFF)
perm = fisherYates(N, seed) → dst[perm[i]] = tmp[i]

// ALGORYTM UNSCRAMBLING (P⁻¹ → XOR ponownie = oryginał)
inv = inversePerm(perm) → applyXOR(tmp, logSeq) → dst

05 / Krytyka własnego rozwiązania
"Dlaczego moje rozwiązanie NIE jest bezpiecznym szyfrem" — §7 wymagań projektu.
Uwaga: Projekt ma cel dydaktyczny, nie kryptograficzny. Każde rozwiązanie traktujemy jako eksperyment ilustrujący różnicę między wizualnym chaosem a bezpieczeństwem informacji.
01. Jaką informację atakujący nadal może odzyskać?
Etap 1: Pełna struktura obrazu jest widoczna — przesunięcie cykliczne zachowuje wszystkie lokalne zależności między pikselami. Histogram wartości identyczny z oryginałem.

Etap 2: Histogram wartości kanałów RGB jest bitowo identyczny z oryginałem (permutacja nie zmienia wartości). Atakujący zna rozkład statystyczny, może rozpoznać typ obrazu.

Etap 3: Rozkład po substytucji XOR jest pseudolosowy, ale entropia nie przekracza 8 bit/kanał. Korelacja między kanałami R/G/B może zdradzać typ obrazu.
→ histogram(permuted) = histogram(original) dla Etapu 2; entropia ≤ 8.0 bit zawsze
02. Co dzieje się przy ataku known-plaintext?
Etap 1: Jedna para pikseli ujawnia oba klucze: k₁ = y'−y (mod H), k₂ = x'−x (mod W).

Etap 2: Z par (orig, scrambled) atakujący odczytuje perm[i] bezpośrednio. Cała permutacja P rekonstruowana w O(N). Można odszyfrować dowolny obraz zaszyfrowany tym kluczem.

Etap 3: Po odtworzeniu P (jak wyżej), atakujący oblicza logSeq[i] = orig[i].R ⊕ tmp[i].R. Cała sekwencja logistyczna ujawniona — można szyfrować inne obrazy tym kluczem.
→ perm[i] bezpośrednio z par (src[i], dst[perm[i]]); logSeq[i] = src[i].R ⊕ inv_perm(dst)[i].R
03. Dlaczego zwiększanie chaosu nie rozwiązuje problemu?
1. Deterministyczność nie zanika: Te same parametry → ta sama sekwencja. Chaos deterministyczny ≠ losowość kryptograficzna.

2. Mała przestrzeń kluczowa: Klucz to (seed, r, x₀) — przestrzeń znacznie mniejsza niż wymagane 2¹²⁸.

3. Precyzja numeryczna: Dla r ≈ 4.0 sekwencja jest nieprzenośna między architekturami FPU — algorytm może tracić odwracalność między różnymi środowiskami.

4. Brak dyfuzji Shannona: Jeden piksel wejściowy wpływa na co najwyżej jeden piksel wyjściowy. AES miesza każdy bit klucza z każdym bitem bloku.
→ x_{n+1} = r·xₙ·(1−xₙ) jest bijekcją na (0,1) tylko dla r≤4; obcięcie do 8-bit niszczy odwracalność dla r=4.0
Wniosek końcowy: Projekt demonstruje fundamentalną różnicę: wizualny chaos ≠ bezpieczeństwo kryptograficzne. Permutacja niszczy struktury przestrzenne, ale zachowuje statystykę. Substytucja XOR zmienia wartości, ale jest trywialna przy known-plaintext. Bezpieczny szyfr wymaga: przestrzeni kluczowej >2¹²⁸, efektu lawinowego, dyfuzji i konfuzji (Shannon 1949). Żaden z 3 etapów tych warunków nie spełnia — i to jest zamierzonym efektem dydaktycznym.
